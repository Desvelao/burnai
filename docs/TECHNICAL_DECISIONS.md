# Technical decisions

| # | Decision | Why |
|---|---|---|
| 1 | **egui/eframe instead of Tauri + React** (deviates from PLAN §3) | Requested by the user; single-language Rust app, no web toolchain. |
| 2 | Docker-only development | Requested by the user; `make` wraps `docker compose run`. |
| 3 | Core/UI split into two crates | Safety logic is testable headless in the container. |
| 4 | SQLite via `rusqlite` (bundled), `PRAGMA user_version` migrations | No external DB; minimal deps. |
| 5 | **Usage: manual entry, or optional automatic polling per account** (deviates from PLAN §2.9/§4) | Claude Code has no documented usage API. At the user's request, an account can use `usage_source=claude_oauth`: token read from its Claude Code credentials file, `GET claude.ai/api/oauth/usage` as in `xfce4-ai-providers-usage-plugin`. Unofficial; readings are labelled `provider` with the source and still expire. Manual remains the default and the fallback. |
| 5a | Browser-like User-Agent + Sec-CH-UA hints (configurable per account) | The endpoint is behind Cloudflare bot checks; same approach as the plugin. A 403 is shown as 'blocked', never as a token error. |
| 5b | Tokens are read-only: never refreshed, written or stored | Refreshing can rotate the refresh token and log the CLI out. Expired token ⇒ show 're-login with `claude`'; no request is made. |
| 5c | **Custom provider = one script per account**, called as `script [args] <kind> [--k=v]` (kinds `usage`, `status` pull; `run` push) | Lets any agent plug in without app changes; all vendor logic stays in the user's script. `status` is fail-closed and re-run by `ProviderAdapter::probe` before every task; subscription still needs the user's confirmation. See `docs/CUSTOM_PROVIDER.md`. |
| 6 | Subscription mode needs: no billing env vars + local login file present + explicit user confirmation | A working CLI call does not prove subscription billing (PLAN §6). Billing evidence only checks that the login file exists; with automatic usage the file is additionally parsed in `core::claude_usage` (see 5b) but the user confirmation is still required. |
| 7 | Prompt via stdin, structured args, scrubbed child env, own process group | No shell injection; billing variables can't leak into the child; STOP can kill descendants. |
| 8 | Consumption since the last reading is added to every later capacity check | Estimates stand in until the user re-enters usage, so repeated batches can't over-commit. |
| 9 | Approvals are in-memory and single-use; restart returns `AwaitingApproval` tasks to `Pending` | Approval must never outlive its batch. |
| 10 | Tasks interrupted by a restart become `Failed`, never auto-rerun | Avoids silent double-spend. |
| 11 | Reordering: ▲/▼ buttons plus a ☰ drag handle in the GUI queue | Built on egui's `dnd_*` payload API (drop line shows the insert position); the TUI is key-only. |
| 12 | Telegram is notify-only; token via env var `PLAN_BURNER_TELEGRAM_TOKEN` | No secrets stored in the DB; approvals stay in-app. |
| 13 | Idle detection via optional `xprintidle`; unknown ≠ idle | Fail closed. |
| 14 | **ratatui TUI (`crates/tui`) alongside the egui GUI**, sharing `core::session` + `Service` | A terminal client for SSH/headless use; no business rules duplicated. |
| 15 | **Single driver process** via an exclusive `flock` on `<data dir>/driver.lock`; other instances are read-only (`Service::read_only`: no tick, propose, start, approve, STOP) | GUI and TUI share one SQLite DB; two schedulers could double-start tasks. The lock is released by the OS on exit/crash. |
| 16 | **Tray daemon (`crates/tray`) as the preferred driver** with a minimal StatusNotifierItem menu (Enabled, Pause/Resume, STOP, Open GUI, Open TUI, Quit) via `ksni` (pure Rust D-Bus, no GTK) | Scheduling must not depend on a window being open; the tray holds `driver.lock` and runs the same `Service` loop. |
| 17 | **Local control socket** (`core::ipc`, `<data dir>/control.sock`, mode 0600, JSON lines). Read-only front-ends forward pause/resume/STOP/approve/reject/propose/run-now and settings and account changes (`SaveSettings`, `SetEnabled`, `*Account`, `SetSubscriptionConfirmed`) to the driver and mirror its run state and pending approvals | Replaces "STOP only in the owning process" (supersedes the limitation in row 15). Requests run through the normal `Service` methods, so billing guard, gates and `probe` still apply; no credentials cross the socket (settings hold none). Account create/edit/delete/policy/confirmation are forwarded too; `start_batch` stays driver-only. Any driver (tray, GUI or TUI) serves it. Approvals stay in the driver's memory (row 9). |
| 18 | **Product identity from `brand.toml`** (name, slug, db file, version, installed binary names), injected at build time by `crates/core/build.rs` into `core::brand`; no hardcoded names in source | Cargo cannot read it for `[[bin]]` names or the package version, so cargo bins use role names (`gui`, `tui`, `tray`), `make dist` installs them under the `[bins]` names, and the build fails if `Cargo.toml`'s version differs from `brand.toml`. `PLAN_BURNER_*` environment variables (custom-provider protocol, data/TUI-log overrides) are intentionally not branded. |
| 19 | **App/tray icon drawn in code** (`core::icon`: SDF shapes, 4x4 supersampling, minimal PNG writer), no image dependency | Keeps dependencies minimal and gives one icon for GUI window, tray and packaging (`tray --export-icon`). The icon encodes state: flame colour (running orange, waiting green, paused amber, stopped red on a red tile, disabled/no-driver grey) plus a badge (pause bars, stop square, slash) and a blue dot when approvals wait. Priority Stopped > Paused > No driver > Running > Disabled > Waiting. The tray ships pixmaps (no themed icon name); the GUI updates its window icon at runtime. |
| 20 | **System path chooser via `rfd` with the xdg-desktop-portal backend** (`core::pick`, no GTK), used by GUI (Browse… button, worker thread) and TUI (Ctrl-B). It only fills the text field; all validation stays in core. No portal or cancel → `None`, typing remains the fallback | Native look with no GTK dependency. In the dev container the portal returns host paths that may not exist under `/work`; the host binary (`make dist`) has no such limit. |
| 20a | **Per-account availability = on-demand switch + weekly schedule** (`accounts.available`, `accounts.availability_schedule`, `core::availability`). Schedule grammar: `;`-separated `days HH:MM-HH:MM` rules in local time (`mon-fri`, `sat,sun`, `fri-mon`, `*`; windows may cross midnight, the tail belongs to the next weekday; empty = always) | Enforced in `engine::preflight` (`Block::AccountUnavailable`), so it also stops user-initiated and approved runs, in `scheduler::plan` (never planned) and in `Service::propose_for`. The switch is a master gate; an unparsable stored schedule fails closed. It only ever narrows when an account may run, so the billing guard is untouched. |
| 21 | **Provider-agnostic run mode** (`models::RunMode`: `inherit`, `plan`, `review`, `auto_edit`) resolved by `engine::effective_run_mode`: per-batch override > task > account > global default; `inherit` defers and finally means "pass nothing" | The Claude adapter maps it to `--permission-mode` (`plan`/`default`/`acceptEdits`); custom scripts receive `--mode=<m>` / `PLAN_BURNER_MODE`; future adapters translate it in `ProviderAdapter::command` (`TaskLaunch.mode`). Fixes runs inheriting the user's own `defaultMode: plan` from their Claude configuration. There is intentionally no "bypass all permissions" level. |
| 22 | **Per-account eligibility overrides** (`models::AccountLimits`, `accounts.lim_*`, migration 0008): start threshold, reserve, idle minutes, allowed hours, usage max age, batch size/minutes, plus separate 5 h (session) threshold/reserve and "ignore the 5 h window". `None` inherits the general setting. A persistent per-account `ignore_limits` switch drops threshold, reserve, idle and allowed hours | Resolved by `Settings::effective_for` / `session_rules`, applied inside `engine::preflight` (so every path agrees), `scheduler::plan_scheduled` (per-account hours/idle; the global gate keeps only enabled/paused/busy) and the runner. Never relaxed by any override or by `ignore_limits`: stale/unknown/unverified usage, a missing weekly reading, the capacity the task needs (`remaining - reserve >= needed`), billing guard, account availability, STOP/pause. Tests: `engine::ignore_limits_never_bypasses_safety`, `usage::ignoring_the_session_window_*`. |
| 23 | **Client parity through `core`**: form models and their mapping/validation live in `core::forms` (`AccountForm`, `TaskForm`, `UsageForm`), shared presentation facts in `core::present` (credential status, billing/priority labels, provenance, stale reading, queue counts), and **every write goes through `Service`** (`save_account`, `save_task`, `task_action`, `record_usage`, `record_actual`, `save_template`, …), forwarded over the control socket when the instance is read-only (new `Request` variants) | GUI and TUI are thin renderers (AGENTS.md rule 9); previously tasks, usage and templates were written straight to SQLite by each client, bypassing read-only mode. `docs/FEATURE_PARITY.md` lists the matrix. The TUI uses `tui-textarea` for editing and full-page editors (no floating windows), like the GUI. |
| 24 | **Templates hold full task defaults and have their own page** (`core::templates`, migration 0009): description, prompt, model, estimates, priority, run mode, budget, timeout, retries, working dir, approval, provider (NULL = any), fallback; never the target account, schedule, expiry or dependencies. CRUD incl. rename and duplicate goes through `Service` (`save_template`, `save_template_form`, `duplicate_template`, `delete_template`) and the control socket | Previously templates were name/prompt/model/estimates only, could not be edited or deleted from any client, and the load buttons were hidden until one existed. “Save as template” upserts by name; the Templates page rejects a new template whose name exists. Old rows load with the defaults of a fresh task. |
| 25 | **Burn before reset** (`Settings.burn_session_hours` / `burn_weekly_hours`, per-account `AccountLimits.burn_*`, migration 0010; `Some(0)`/`None` = off, account `None` inherits). When a window's *known, future* reset is at most N hours away, `usage::check_capacity` uses threshold = 0 and reserve = 0 for that window only | Lets capacity that would expire at the reset be spent, while keeping the reserve early in a window. Fail closed: an unknown reset time never triggers it, and it never relaxes stale/unknown/missing usage, `ResetPassed`, billing, or `remaining >= needed`. Tests: `usage::burn_*`, `engine::burn_before_reset_global_and_account_override`. |
| 26 | **Burn buttons** (`Service::set_burn_before_reset`, `set_account_burn`, `burn_now`). The on/off buttons write the existing burn fields from #25 with fixed defaults (5 h window last 1 h, weekly last 24 h; per-account OFF is an explicit 0 h override so it beats a general ON). **Burn now** plans one manual batch with the account's `ignore_limits` forced on for that plan, and a `burn` flag travels `Proposal` -> `ApprovedBatch` -> `BatchRequest` so the runner applies the same switch to that batch only. 'With approvals' queues it under Approvals; 'without approvals' starts it at once (one batch at a time, so with all accounts only the first eligible one starts). | A user click replaces the approval step only when the user asks for it explicitly (inline confirm). Never relaxed: stale/unknown usage, billing guard, availability, STOP/pause, and `remaining >= needed`. Writes an audit entry `burn_now`. Tests: `service::burn_now_never_bypasses_safety`, `burn_now_with_approval_*`, `burn_now_without_approval_*`, `burn_buttons_toggle_*`. |
| 27 | **Duplicate task, queue-from-template and recurring tasks** (`tasks::duplicate`, `Service::queue_from_template`, `tasks.repeat`, migration 0011, `core::recurrence`). Repeat grammar: `every:<N><m\|h\|d\|w>` (min 5 min), `daily:HH:MM`, `weekly:<days>@HH:MM`. `tasks::set_status` (and `expire_due`/`recover_interrupted`) call `tasks::enqueue_next` on Completed/Failed/Expired | The successor is an ordinary Pending task gated by `schedule=after:<time>`, so it passes every scheduler, preflight and billing check; nothing new can start a run. Unparsable rules fail closed (nothing queued). One live instance per name+rule. Tests in `tasks` and `recurrence`. |
| 28 | **Task import and a scripting CLI** (`core::import`, `Service::import_tasks` / `import_file` / `list_tasks` / `reorder_tasks`, IPC `list_tasks`, `import_tasks`, `reorder_tasks`, `crates/cli`). Formats: JSON (array or `{"tasks":[...]}`, unknown keys rejected) and Markdown (headings with `key: value` settings, or `- name: prompt` bullets), hand-parsed - no new dependency. Each record goes through the normal `TaskForm` save, so validation, the pending status and the approval default are unchanged and an import never starts anything; bad records are reported and skipped, `depends_on` takes ids or names. The CLI only sends control-socket requests to the driving instance (never opens the DB, never touches credentials), so the single-driver rule holds; request lines are capped at 2 MiB and files at 1.5 MB. | One implementation for GUI, TUI, CLI and any script (decisions #17, #23); JSON/Markdown cover generated and hand-written backlogs without a CSV dependency. |
| 29 | **Dedicated scheduler daemon (`crates/daemon`); every other binary is a pure client** (supersedes the driver parts of 15, 16 and 17) | Only the daemon calls `session::open_driver_service` (takes `driver.lock`, serves `control.sock`, ticks the scheduler). GUI, TUI, tray and CLI use `open_client_service`: they never lock or drive, read the DB directly and forward every write/action to the daemon. Closing a client can no longer stop or hand over the scheduler, and there is no takeover (`try_promote` removed). With no daemon, clients show `SchedulerStatus::Offline` and offer **Start scheduler** (`core::launch::spawn_daemon`, structured args, no shell); a socket that accepts but does not answer shows `Unreachable`. Clients never auto-start it. The tray only opens the GUI and starts the daemon (no TUI/CLI launching, no terminal-emulator lookup). |
| 30 | **Per-user installer (`install.sh`) and install guide (`docs/INSTALL.md`)** | Profiles `gui`/`tui`/`cli`/`all` always include the daemon (only it runs tasks) and the tray (skippable). The script downloads the GitHub release tarball, verifies its SHA-256 before unpacking, rejects unsafe archive paths, and writes only under the prefix and `~/.config/systemd/user`. Names come from the `MANIFEST` that `make dist` writes from `brand.toml`, so the script hardcodes no product names. A receipt in `<prefix>/share/install-receipts/` lets `--uninstall` remove exactly what was installed and keep user data. `make install-test` runs it against `dist/` in the container. |
| 31 | **GUI bundles DejaVu Sans as the last fallback font** (`crates/app/assets/fonts/DejaVuSans.ttf`, ~750 KB, registered in `theme::fonts`; licence in `LICENSE-DejaVu.txt`) | egui's default fonts lack some symbols the GUI uses (arrows, dots, dingbats) and drew them as boxes. Embedding keeps rendering identical on every machine instead of relying on system fonts. It is only a fallback, so normal text still uses egui's fonts. The TUI is unaffected (terminal font). |
